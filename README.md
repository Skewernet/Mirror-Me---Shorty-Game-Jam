# MIRROR ME — Shorty Game Jam 2026

A first-person PS1-inspired psychological horror game about a looping house and a reflection that learns to move without you. Theme: **INVERTED**.

Original concept and direction by Skewernet. Development began October 22, 2026, with AI-assisted prototyping and implementation using ChatGPT/Codex.

## First encounter — playable slice 0.2

An authored domestic hallway with aged olive wallpaper, dark panelling, worn carpet, warm lamps and a cold mirror. Explore the house, inspect the paper on the console, and pay attention to your reflection. This is a short first encounter with a complete exit/ending and replay, not the complete jam game.

Includes accelerated walking, collision against walls and furniture, a continuous hallway circuit, a real reflected room, a player figure that follows/delays/acts independently, a small pocket inventory, drawer/key interaction, an animated exit door, title/pause/settings menus, original synthesized sound and seven **synthetic provisional voice performances** with subtitles.

## Run locally

No build step, package install, API key or external asset service is needed. From this repository:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

Open the local server in a desktop WebGL browser. Serve over HTTP; double-clicking `index.html` will not reliably load JavaScript modules. Click ENTER to capture the mouse and enable audio. The onboarding UI does not provide a supported web preview; the cloud server is used for internal validation.

Three.js, textures generated by project code and voice clips are served locally. No CDN or browser speech service is required. Audio inference tools are only needed to regenerate takes; they are not game dependencies.

## Controls

| Input | Action |
| --- | --- |
| WASD / arrow keys | Walk |
| Mouse | Look |
| E | Inspect, collect, open, or automatically use the key |
| Tab | Open/close the pocket inventory |
| Escape | Pause; from inventory, return to the pause menu |
| Menu settings | Mouse sensitivity, master volume, voice playback, optional walking motion |

Head motion is off by default. Pausing or opening the pocket stops gameplay and audio. Starting again resets the encounter and inventory while preserving the current comfort settings. No sprint, combat, mobile controls or persistent save system is included.

## Validate

```sh
node --test tests/*.test.mjs
node tests/browser.cjs
```

The second command requires the local server, Playwright and system Chromium. They are available in the prepared cloud environment. Outside it, install Playwright in your development environment and supply `CHROMIUM_PATH` if necessary. Optional `MIRROR_TEST_URL` selects a test server and `MIRROR_TEST_OUTPUT` selects the screenshot directory (default: `/tmp/mirror-me-checks`). Browser tests use the explicit `?test=1` deterministic harness; the harness is absent during normal play.

Nine unit tests cover movement collision and progression. The browser check walks the actual circuit, exercises the mirror encounter, early interactions, inventory, pause, occlusion, collisions, the animated exit, ending/restart, and fetches/decodes all seven voices. A separate normal-play check verified live movement, Escape, settings, inventory pause and resize without page errors. Software-rendered cloud testing does not establish target-device frame rate or subjective sound quality. Firefox and human headphone playtesting remain outstanding; Firefox download was blocked by environment egress policy.

## Production safety

The existing production project is **[mirror-me](https://mirror-me.pages.dev)**. Authenticated inspection confirmed its GitHub source is `Skewernet/Mirror-Me---Shorty-Game-Jam`, production branch `main`, with automatic production deployments enabled. The earlier pushes did not create deployment records, so a push alone must not be treated as a successful release.

The owner-approved slice was uploaded directly and verified live: all 24 runtime assets matched revision `11c84c7`. The environment now has working secure Cloudflare access. Build settings are `python3 tools/stage_pages.py --output-dir dist`, output directory `dist`, repository root. This packages runtime assets and a revision/hash manifest instead of publishing development tools.

For an approved release, use `python tools/deploy_pages.py --github-build` to build the remote production branch, or `python tools/deploy_pages.py` for Direct Upload. Both verify the live `build-id.json` and exact asset hashes. `python tools/deploy_pages.py --verify-only` checks whether the current clean checkout matches production without publishing. GitHub main must contain the intended commit before using the Git build route. [Connection and operating instructions](CLOUDFLARE_SETUP.md).

Further production changes require approval of the specific changes. No automatic deployment runs at environment startup. Do not modify Morlins Quest or Skewer Signals.
